# TutorialOverlay

Экранный оверлей для пошаговых туториалов в любом приложении Windows. Управляется Claude Code через MCP.
Один exe на C# / .NET 8. Написан с нуля: без NuGet-пакетов и сторонних ассетов. Вся графика (кольца, стрелки,
иконки, галочки) рисуется векторно в коде. Текст выводится системным UI-шрифтом Windows через ОС, файлы шрифтов
в программу не входят.

## Сборка и запуск

```powershell
dotnet publish -c Release -o publish        # → publish\TutorialOverlay.exe (~350 КБ, нужен .NET 8 Desktop + ASP.NET runtime)
$env:TUTORIAL_OVERLAY_KEY = "<длинный-секрет>"
publish\TutorialOverlay.exe                  # http://127.0.0.1:7788/mcp
```

Параметры: `--port 7788` (1–65535; неверное значение — код выхода 1), `--key KEY`, `--no-anim`, `--show-inactive` (не прятать отметки, когда приложение
не на переднем плане), `--verbose`. Ключ берётся из `--key`, из переменной `TUTORIAL_OVERLAY_KEY` или из
`%LOCALAPPDATA%\TutorialOverlay\key.txt` (файл создаётся при первом запуске).

Порт по умолчанию — 7788, его можно поменять полем `port` в `config.json` (параметр `--port` главнее).

**Один сервер и один агент.** На пользователя работает ровно один сервер — и один значок в трее. Второй запуск
(на любом порту, хоть одновременно с первым) не стартует: если exe запустили вручную, он показывает окно
«TutorialOverlay уже запущен: 127.0.0.1:7789 (PID …)», если его вывод читает агент — печатает событие
`{"event":"already_running","port":7789,"pid":…,"url":…,"advice":…}` (дождавшись, пока первый запишет свой адрес)
и выходит с кодом 2. Где работает сервер, всегда видно в `%LOCALAPPDATA%\TutorialOverlay\server.json`
(`port`, `pid`, `url`). Параметра `--instance` больше нет.

Сервер обслуживает **одного агента за раз**. Первая MCP-сессия (`Mcp-Session-Id`), вызвавшая инструмент, занимает
его; любой вызов из другой сессии получает отказ `busy: … held by another agent` и ничего не делает (доступны только
`initialize`, `tools/list`, `ping`; поток уведомлений тоже только у владельца). Второй агент ждёт своей очереди
инструментом `wait_for_turn(timeoutMs)` — он возвращает `{"granted": true}`, как только сервер освободился. Сервер
освобождается:

- когда клиент владельца закрылся. Клиент MCP держит открытым поток уведомлений (`GET /mcp`), пока работает; при выходе
  соединение рвётся (Claude Code при `/exit` не шлёт `DELETE`, но соединение закрывается всегда). Если поток не
  открылся снова за 5 секунд, сервер свободен (`client disconnected`). Пока поток открыт, сервер остаётся за владельцем,
  сколько бы агент ни молчал;
- когда владелец вызывает `release` или закрывает сессию (HTTP `DELETE`);
- у клиента без потока — после 3 минут молчания (30, пока идёт его туториал).

Поток уведомлений может открыть любая сессия, но события получает только владелец. Открытие и закрытие потоков,
`DELETE` и отклонённые без ключа запросы видны в журнале. События `client_connected` / `client_released`.

**Остановка.** `--stop` просит запущенный сервер закрыться так же, как пункт «Закрыть» в его меню: значок пропадает
из трея, `server.json` удаляется. При перезапуске из окна настроек значок старого процесса убирается до старта нового.

**Если процесс убит принудительно** (`taskkill /F`, диспетчер задач, остановка фоновой задачи), сам он значок убрать не
может, а Windows оставляет такой значок, пока над ним не проведут мышью. Поэтому значок регистрируется с постоянным
GUID (он зависит от пути к exe), и убрать его может любой процесс того же exe:

- сервер запускает **сторожа** (`--tray-guard`, без окон и значка; двумя шагами, чтобы он оказался вне дерева
  процессов сервера и пережил `taskkill /T`). Сторож ждёт завершения сервера и сразу убирает его значок и `server.json`;
- следующий запуск сервера тоже сначала убирает оставшийся значок прошлого.

Если Проводник перезапустился, значок появляется снова.

**Значок в трее** показывает, что сервер запущен: маленькая карточка шага. Полоска сверху во время туториала показывает
его прогресс, точка в углу зелёная, если агент обращался за последние 5 минут, серая — если нет. Подсказка при наведении: порт, когда агент
обращался последний раз, текущий туториал и шаг. Левый клик открывает настройки, правый — тёмное меню: «Туториалы ▸»
(сохранённые туториалы, щелчок запускает), «Настройки…», «Скопировать ключ», «Скопировать адрес MCP», «Открыть папку
настроек», «Остановить туториал», «Закрыть TutorialOverlay».

**Окно настроек** (вкладки «Сервер», «Вид», «Горячие клавиши») нарисовано в тёмном стиле карточки: тумблеры,
скруглённые поля, образцы цветов для отметок, тёмный заголовок окна. Пишет в `config.json` и сразу применяет изменения.
`--settings [server|look|keys]` открывает его сразу при запуске.

**Порт.** Рядом с полем порта — живая проверка: «свободен ✓», «занят: программа (PID)» или «на нём работает этот сервер».
«Подобрать» оставляет введённый порт, если он годится, иначе подставляет первый свободный из 7788–7899. Занятый порт
сохранить нельзя, а перезапуск не начнётся, если новый порт успели занять, — рабочий сервер не закроется впустую.
Новый порт начинает работать после перезапуска, окно предложит перезапустить сервер. Адрес в `.mcp.json` при этом
нужно поменять самому.

«Для агента → Скопировать команду подключения» (и такой же пункт в меню трея) кладёт в буфер готовую строку
`claude mcp add --transport http tutorial-overlay http://127.0.0.1:<порт>/mcp --header "Authorization: Bearer <ключ>"`
с портом из поля — её отдают агенту в чат или выполняют в терминале.
Если идёт туториал, язык, цвет и хоткеи из его spec действуют до его конца.

Сервер слушает только `127.0.0.1`. Ключ принимается только в заголовке: `Authorization: Bearer` или `X-Overlay-Key`
(ключ в адресе, `?key=`, больше не принимается — он попадает в журналы и историю команд). Чужие `Origin` отклоняются.

**stdout** — одно JSON-событие на строку, **stderr** — диагностика. Claude Code может запустить exe через
Monitor и реагировать на события без вопросов «готово?». stdout пишется отдельным потоком: если его перестали
читать, оверлей не замирает, а старые строки из очереди отбрасываются (инструмент `events` их по-прежнему отдаёт).

**Журнал** — `%LOCALAPPDATA%\TutorialOverlay\logs\overlay.log` (диагностика и события; при 2 МБ файл сменяется,
хранятся 3 предыдущих). Нужен, когда exe запущен без консоли и stderr никто не видит.

### Подключение к Claude Code

В корне репозитория лежит `.mcp.json` (сервер `tutorial-overlay`, ключ подставляется из `${TUTORIAL_OVERLAY_KEY}`).
Для другого проекта:

```
claude mcp add --transport http tutorial-overlay http://127.0.0.1:7788/mcp --header "Authorization: Bearer <ключ>"
```

## Инструменты MCP

| Инструмент | Что делает |
|---|---|
| `draw(shapes, anchor, dismissOnClick, …)` | отметки вне туториала; клик гасит отметку и доходит до приложения |
| `clear(id?)` | убрать отметки |
| `start_tutorial(spec)` | запустить туториал (показан только текущий шаг) |
| `append_steps(steps)` | дописать шаги (с `keepOpen` туториал ждёт их после последнего) |
| `goto_step(index\|id\|relative)` | перейти к шагу; цели снова показаны |
| `complete_step(expectIndex?)` | засчитать шаг от имени агента |
| `stop_tutorial()` | остановить |
| `status()` | состояние, прямоугольники целей и причина видимости (`visible/occluded/minimized/inactive/…`) |
| `describe(app)` | окна процесса и дерево UI Automation с физическими прямоугольниками и `rel`-смещениями |
| `screenshot(anchor)` | снимок окна/элемента **без** рисунков оверлея; `includeOverlay: true` — с ними |
| `events(since, timeoutMs)` | события с long-poll (дублирует stdout и MCP-уведомления); `gap` — часть событий после `since` уже выпала из буфера (1000 последних) или не уместилась в ответ (200) |
| `hint(text, title?, highlight?)` | ответ агента в карточке шага (например, после события `help`) |
| `pick(anchor, count, prompt)` | калибровка: пользователь кликает точку, агент получает смещение от якоря, цвет, элемент UIA и готовый `suggestedAnchor`; клик по умолчанию до приложения не доходит, Esc — отмена |
| `find_text(text?, anchor, within, match, lang)` | найти надпись на экране встроенным в Windows OCR: прямоугольник, центр, `rel` и `suggestedAnchor` с `find: {text}`; без `text` — весь распознанный текст области |
| `validate(spec?)` | проверить туториал до запуска (или текущий): по каждому шагу видна ли цель сейчас, а если нет — почему |
| `wait_for_turn(timeoutMs)` | дождаться, пока другой агент освободит сервер (после ответа `busy`), и занять его |
| `release()` | закончить работу: сервер свободен для другого агента, идущий туториал продолжается |
| `ask(question, options, input)` | спросить пользователя в панели над карточкой и дождаться ответа: кнопкой (`{choice, label}`) или текстом (`{text}`) |
| `ask_area(prompt)` | попросить обвести место на экране карандашом и дождаться: границы, штрихи, элемент UIA в центре и картинка области |

## Сущности

На холсте (клики проходят насквозь в приложение):

- `circle` — кольцо; `rect` — рамка (без `w/h` обводит элемент якоря); `arrow` — стрелка (сама целится в цель,
  хвост смотрит к центру экрана);
- `badge` — номер; `label` — подпись; `info` — инфо-блок с заголовком и значком;
- `check` — галочка; `checkbox` — чекбокс, который сам ставит ✓, когда цель выполнена (удобно для ячеек FL);
- `dim` — затемнение экрана с «окнами» на целях.

Кликабельные (отдельные окна, фокус у приложения не забирают):

- `button` — кнопка в любом месте экрана: `{text, id, action: done|next|back|skip|stop|undo|dismiss, style}`;
  шлёт событие `button`;
- **карточка шага** — «ШАГ n / N», прогресс, заголовок, текст, чек-лист целей, «Назад», «↶» (отменить последнее
  попадание), «Пропустить», «Готово», «✕» (стоп) и свои кнопки шага (`buttons`).

Раскладка без наложений: кольца соседних целей сужаются, подписи/инфо/кнопки без явных `x,y` ищут свободное
место вокруг цели (подпись встаёт у хвоста стрелки), карточка обходит всё нарисованное. Карточку можно
перетащить мышью — тогда она остаётся на месте.

## Якоря

```json
{ "process": "FL64", "window": "подстрока заголовка", "title": "окно ИЛИ Pane/Window в UIA",
  "element": [{ "name": "Channel rack", "role": "Pane" }, { "name": "…" }],
  "origin": "topleft|center|…", "offset": [dx, dy], "relativeTo": "frame|client" }
```

- Имена сравниваются подстрокой без учёта регистра. Из одноимённых элементов берётся самый большой
  (`pick: largest`). Это нужно для FL, где каждое подокно в UIA представлено двумя Pane.
- Резолвер просматривает **все** окна процесса, в том числе меню и диалоги. UIA опрашивается в фоновом потоке,
  а отметка каждый кадр берёт текущую позицию окна, поэтому едет за ним без задержки.
- Отметка прячется, если окно свёрнуто, закрыто, перекрыто другим окном или приложение не на переднем плане
  (`hideWhenInactive`, по умолчанию включено). Пока пользователь в другом окне, условия шага заморожены. При
  возврате всё появляется на том же шаге; если окно пересоздано, якорь находится заново.
- Клики сопоставляются по **процессу** окна под курсором, а не по заголовку.

**Якорь по тексту** — для программ, которые рисуют интерфейс сами и ничего не отдают в UIA (FL Studio):

```json
{ "process": "FL64", "element": { "name": "Channel rack" }, "find": { "text": "Kick", "match": "contains", "index": 0 }, "offset": [-40, 0] }
```

Надпись ищется встроенным в Windows распознаванием текста (`Windows.Media.Ocr`, вызывается напрямую через WinRT,
без дополнительных библиотек) по собственным пикселям окна, поэтому работает и под другими окнами. Точка якоря —
центр найденного текста, `offset` отсчитывается от него. Отметка следует за надписью при прокрутке (поиск раз в
0,7 с). `match`: `contains` (по умолчанию), `exact` (вся строка), `regex`; ошибки распознавания вида «буква вместо
похожей» (l/I, 0/O — до одной на 6 букв) прощаются, но только в целых словах: «Kicks» не найдёт «Kick». `index` — номер вхождения сверху вниз и слева направо, `within: [x,y,w,h]` — часть элемента.

Язык распознавания выбирается по алфавиту запроса: кириллица — русский распознаватель, латиница — английский
(английский превращает русский текст в мусор, русский читает «You» как «Уои»). `find_text` без `text` читает обоими и
для каждой строки оставляет подходящий вариант. `lang` задаёт распознаватель явно. Распознавания идут по очереди:
движок Windows не выдерживает два одновременных. Как OCR прочитал область, показывает `find_text` без `text`.

Шаблоны (`find: {template}`) ищутся в два прохода: быстрый на картинке вдвое меньше выбирает 8 кандидатов, точный
в полном разрешении выбирает из них — так похожие кнопки соседних строк («808 Kick» и «808 Snare») не путаются.

Снятые шаблоны хранятся на диске (`%LOCALAPPDATA%\TutorialOverlay\templates\`) и переживают перезапуск, а
сохранённый туториал несёт используемые шаблоны внутри своего файла (`"templates": {id: PNG в base64}`), поэтому
запускается из меню трея и на другом компьютере.

**Проверка перед запуском** — `validate(spec)` разрешает все якоря туториала прямо сейчас. Ошибки (процесс не
запущен, шаблон не снят, шаг не разобран) нужно исправить. Предупреждения на поздних шагах часто означают то, что
откроет предыдущий шаг; `occluded` и `inactive` значат лишь, что сейчас впереди другое окно.

## Шаги и условия

```json
{ "id": "kick", "title": "…", "text": "…", "anchor": { … }, "toggle": true, "dim": 0.4, "numbered": true,
  "targets": [{ "name": "Шаг 1", "shapes": [ … ], "check": { "at": [335, 93], "expr": "g>140" },
                "button": "left|right|any", "optional": false, "doneStyle": "hide|check" }],
  "until": [ "all_clicked", { "type": "appear", "title": "Piano roll" }, { "type": "disappear", "title": "Piano roll" },
             { "type": "pixel", "anchor": { … }, "at": [x, y], "expr": "r>140 && g<100" }, { "type": "count", "count": 3 } ],
  "untilMode": "any|all", "buttons": [{ "id": "yes", "text": "Да" }], "controls": ["back", "undo", "skip", "done", "stop"] }
```

- Без `until`: шаг с целями завершается, когда кликнуты все цели. Шаг без целей ждёт «Готово», хоткей
  или `complete_step`.
- `disappear` срабатывает, только если цель сначала была замечена на экране.
- `toggle`: повторный клик по погашенной цели снова её зажигает. Если у цели есть `check`, состояние берётся
  из пикселя, и toggle получается сам собой.
- Выражения пиксельной проверки: каналы `r g b lum max min sat`, разность вида `r-g`, операторы
  `> >= < <= == !=`, связки `&&` и `||`, близость к цвету `~#1AD28F:40`.

Ещё условия:

- `{ "type": "key", "keys": ["F6", "Ctrl+S"] }` — нажато сочетание, пока приложение на переднем плане. Клавиши
  читаются только пока такое условие активно, и наружу сообщается только совпадение (`key_matched`): остальные
  нажатия нигде не записываются.
- `{ "type": "drag", "from": { "element": { "name": "Browser" } }, "to": { "element": { "name": "Channel rack" } } }` —
  перетаскивание из одной области в другую. Области: границы якоря, `rect:[x,y,w,h]` от точки якоря или `radius`.
  Рисуется как источник → стрелка → зона сброса.
- `{ "type": "uia", "element": { "name": "Bold" }, "property": "toggle", "equals": "on" }` — состояние элемента:
  `exists`, `name`, `value`, `toggle`, `selected`, `expanded`, `enabled`, `focused`, `text`. Сравнение —
  `equals`, `contains` или `matches` (regex), плюс `not`. При изменении значения приходит событие `uia_changed`.

**Провести по траектории** — фигура `path` и условие `trace`:

```json
{ "type": "trace", "anchor": { "element": { "name": "Playlist" } }, "path": [[40, 60], [180, 20], [320, 80]],
  "hold": ["Shift"], "tolerance": 24, "coverage": 0.85 }
```

Точки — смещения от точки якоря, через них идёт плавная кривая (`smooth: false` — ломаная). Рисуется пунктиром со
стрелками направления, точкой старта, стрелкой в конце и бегущим огоньком; пройденная часть закрашивается. Засчитывается,
если мышь с зажатой кнопкой прошла не меньше `coverage` пути от начала (`ordered: false` — в любом направлении), ни
разу не отходя дальше `tolerance` px. `hold` — клавиши, которые нужно держать всё время (то же поле есть у `drag`);
рядом со стартом плашка «Держите Shift», зелёная, пока клавиши зажаты. События: `trace_done`, `trace_off` с причиной
`off_path`, `too_short`, `released_key`, `key_not_held` или `start_at_the_beginning` и долей пройденного пути.
Шажок показывает на начало траектории.

**Прокрутить** — условие `scroll`:

```json
{ "type": "scroll", "in": { "element": { "name": "Browser" } }, "direction": "down", "notches": 5 }
{ "type": "scroll", "in": { "element": { "name": "Browser" } }, "direction": "down", "until": "visible" }
```

Считает щелчки колеса над областью в нужную сторону (`up/down/left/right`); `until: "visible"` — пока цели шага не
окажутся на экране. Рядом с областью — значок мыши с бегущими стрелками и счётчиком. Событие `scroll_done`.
Считаются колесо, тачпад и полоса прокрутки. Сообщения колеса складываются (щелчок — 120 единиц, тачпад шлёт много
мелких порций). Но браузеры и многие программы берут прокрутку с тачпада напрямую, без сообщений колеса, поэтому
оверлей ещё и смотрит на саму область: ~8 раз в секунду сравнивает её собственные пиксели (без наших рисунков) и
видит, куда сдвинулось содержимое — уехало вверх, значит прокрутили вниз (~60 px на щелчок при 100 %). Засчитывается
большее из двух. Сдвиг идёт в счёт, только если курсор над областью и только что был ввод пользователя, — так чат,
лог или видео, которые прокручиваются сами, шаг не засчитают. `until: "visible"` тоже работает без сообщений колеса:
шаг засчитается, когда скрытые цели появятся на экране.

Движения мыши (только при зажатой кнопке) и колесо читаются, лишь пока текущий шаг их требует; наружу уходит только
результат, а не путь мыши.

**Цель за краем панели** — отдельный шаг прокрутки писать не нужно. Если цель шага ушла за край своей панели (у
элемента UIA прямоугольник вне видимой части; надпись или шаблон перестали находиться), у этого края появляется значок
колеса с бегущими стрелками, а Шажок встаёт рядом и говорит «Прокрутите вниз». Направление: у элементов UIA — по их
прямоугольнику, тогда видно и расстояние («≈ 6» щелчков); у надписей и шаблонов — по тому, куда они двигались перед
исчезновением, или у какого края их видели в последний раз (расстояния тут нет). Прокрутили мимо — подсказка
разворачивается. Цель появилась — Шажок идёт к ней, отметка снова на ней. Пока надпись не видна, она перечитывается
вдвое чаще. Всё это внутри оверлея: агенту не уходит ни снимков, ни событий; `anchor_found/lost` — не чаще раза в 3 с
на якорь, чтобы прокрутка длинного списка туда-сюда не засыпала агента событиями.

**Клик, который открывает окно** — поле цели `opens`:

```json
{ "anchor": { … }, "opens": { "title": "Piano roll" } }                         // подокно внутри программы
{ "anchor": { … }, "opens": { "process": "chrome", "timeoutMs": 15000 } }        // окно другой программы
```

Цель засчитывается, только когда после клика появилось **новое** окно или панель: окно, которое было открыто
раньше, не считается. Если за `timeoutMs` (по умолчанию 6 с) ничего не появилось, цель остаётся гореть, а агенту
приходит `no_effect`; успех — событие `opened`. Пока пользователь работает в открывшемся окне другой программы,
шаг не замораживается, и его карточка остаётся видна.

**Цепочка внутри шага** — `"sequence": true`: цели показываются по одной, по порядку. Типичный случай — правый клик
по каналу, затем пункт в открывшемся меню:

```json
{ "sequence": true, "targets": [
  { "name": "Правый клик по FLEX Bass", "button": "right", "anchor": { "element": { "name": "Channel rack" }, "offset": [224, 272] } },
  { "name": "Пункт «Piano roll»", "anchor": { "windowClass": "TQuickPopupMenuWindow", "offset": [40, 120] },
    "opens": { "title": "Piano roll" } } ] }
```

Меню — отдельное окно процесса, поэтому якорем служит само окно меню. Без `offset` обводится всё меню; точное
место пункта снимается через `pick(anchor: { windowClass: … }, passThrough: true)`. Если меню закрылось, а нужный
пункт так и не выбрали, предыдущая цель загорается снова, и приходит событие `sequence_reset`.

**Сетка** — одна запись вместо многих целей:

```json
{ "name": "Шаг {col}", "grid": { "from": [335, 93], "step": [24, 45], "cells": [1, 5, 9, 13] }, "check": { "expr": "g>140" } }
```

`from` — центр первой ячейки относительно точки якоря, `step` — расстояние между центрами. Можно задать `rows`
и `cols` или список `cells` (`[[ряд, столбец], …]` или просто номера столбцов первого ряда, всё с единицы).
Фигура по умолчанию — чекбокс размера `w × h`. Значения `from` и `step` проще всего получить через
`pick(anchor, count: 2)` по двум соседним ячейкам: ответ содержит `gridHint`.

## Маскот «Шажок»

Ожившая карточка шага: подлетает к цели, показывает на неё рукой и говорит реплику шага в облачке. На «лбу» —
полоска прогресса туториала.

- Место выбирает из 16 вариантов вокруг цели: на экране; не на цели, отметках, подписях и карточке; не на линии от
  курсора к цели (там пойдёт рука пользователя); над пустым фоном, а не над плотным интерфейсом (оценка по
  собственным пикселям окна программы); при прочих равных — поближе к тому месту, где стоит. Облачко тоже выбирает
  свободную сторону. Когда окно программы двигают, едет вместе с целью.
- К следующей цели: если рука дотягивается с текущего места — только переводит руку; если новое место в паре шагов —
  идёт ногами; дальше — исчезает и появляется уже на месте, без долгой дороги через экран. Между шагами и без цели
  стоит на месте.
- Подсветка цели появляется вместе с ним: когда он закончил появляться или остановился (но не позже чем через 1,5 с).
- Попадание — подпрыгивает и летит к следующей цели; промах — качает головой и снова показывает; «?» — думает, пока
  агент готовит подсказку; конец туториала — празднует. Прячется вместе с отметками, когда приложение не впереди.
- Реплика — поле шага `say` (коротко, до ~60 символов), иначе заголовок шага.
- Всё движение считает оверлей сам по координатам цели и событиям — агент маскотом не управляет, токены на него не
  тратятся. Отдельное маленькое окно, ~2% одного ядра.
- Выключается в настройках («Вид → Маскот») или в spec: `"mascot": false`.

## Конец туториала и библиотека

После последнего шага карточка не исчезает, а показывает «Туториал пройден!» и предлагает:

- **Сохранить туториал** — в библиотеку `%LOCALAPPDATA%\TutorialOverlay\tutorials\` (событие `tutorial_saved`);
- **Продолжить обучение** — карточка переходит в ожидание, агенту приходит `continue_requested`, он дописывает следующий
  урок через `append_steps`, и пользователь продолжает на той же карточке. Кнопка видна, только если агент обращался
  к серверу за последние 30 минут;
- **Пройти ещё раз** — тот же туториал с первого шага;
- **Закрыть**.

Выбор приходит событием `outro`. Отключается полем `"outro": false` в spec.

Сохранённый туториал — обычный JSON со spec (вместе с шагами, дописанными через `append_steps`). Что с ним делать дальше:

- пройти снова без агента — меню значка в трее → «Туториалы»;
- запустить из агента — `start_tutorial({ "name": "fl-instrument-setup" })`, можно со `startAt`;
- `list_tutorials`, `save_tutorial(name?, spec?)`, `delete_tutorial(name)`;
- поделиться — файл из папки библиотеки переносится на другой компьютер как есть, вместе с шаблонами.

Сохранение под существующим именем перезаписывает файл; `save_tutorial` тогда отвечает `replaced`. Имена устройств
Windows (`con`, `nul`, `com1`…) получают суффикс `-1`.

**Масштаб экрана.** Смещения в spec — физические пиксели, они верны только для масштаба, при котором их измерили.
Сохранённый туториал запоминает его (`"scale": 1.65`, можно указать и самому). Если туториал запущен при другом
масштабе, пиксельные поля (`offset`, `x`, `y`, `w`, `h`, `r`, `from`/`to`/`step` из чисел, `at`, `path`, `points`,
`within`, `rect`) умножаются на отношение масштабов, а ответ `start_tutorial` сообщает об этом в поле `scale`.
Толщины линий, `pad` и `tolerance` и так пересчитываются под масштаб при рисовании и не трогаются.

## Проверка spec на опечатки

Разбор spec нестрогий: неизвестное поле просто игнорируется, поэтому опечатка (`"untill"`, `"tagrets"`) молча
меняет поведение шага. `start_tutorial`, `append_steps` и `draw` возвращают `warnings`, а `validate` — `unknownFields`:
каждое поле, которое парсер не читает, с подсказкой «did you mean», а также неизвестные типы условий, фигур и кнопок
карточки:

```
steps[2].untill: unknown field (did you mean 'until'?) — ignored
steps[0].targets[1].shapes[0].type: unknown shape 'circel' (did you mean 'circle'?) — nothing is drawn for it
```

## Программы «от имени администратора»

Windows не пускает обычный процесс к вводу и интерфейсу процесса с правами администратора. Цели в такой программе
получают видимость `elevated`, карточка объясняет, что TutorialOverlay нужно тоже запустить от имени администратора,
а `validate` считает это ошибкой. Сторож хуков в это время не переставляет их впустую.

## Помощь пользователю

На карточке есть кнопка **«?»** (хоткей **Ctrl+Alt+H**). Она раскрывается в два варианта: **«Не вижу, куда жать»**
и **«Не понимаю, что делать»**.

- Агенту приходит событие `help`: причина, у каждой цели — видна ли она и почему (`visible`, `occluded`, `minimized`,
  `inactive`, `element not found`…) и где она на экране, последние промахи на шаге, активное окно и курсор.
- На «Не вижу» оверлей сам на 6 секунд затемняет экран вокруг целей и пускает от них волны.
- Картинки набросков хранятся в `%LOCALAPPDATA%\TutorialOverlay\help\`: при запуске остаются последние 50 и не
  старше 14 дней.
- В окне «Другое» есть **карандаш** («Обвести»). Он замораживает картинку экрана, и пользователь обводит мышью место,
  о котором пишет. Enter или правый клик — готово, Ctrl+Z или Backspace — убрать последний штрих, Delete — стереть всё,
  Esc — выйти без изменений. Повторное нажатие на карандаш дорисовывает к уже сделанному. Обводка остаётся на экране
  до ответа агента. В событии `help` появляется поле `sketch`: `bounds` и `center` в пикселях экрана, `strokes`
  (у каждого штриха `shape`: `loop` | `line` | `dot`, `from`, `to` и до 48 точек), `atCenter` (окно, цвет и элемент UIA
  в центре обводки, `rel` от якоря первой цели шага, `suggestedAnchor`) и `image` — путь к PNG с этим местом и обводкой
  в `%LOCALAPPDATA%\TutorialOverlay\help\`.
- Ответ агента — инструмент `hint(text, title?, highlight?)`: текст появляется прямо в карточке текущего шага. До
  ответа карточка пишет «Передал ассистенту — сейчас подскажу».
- Если цель не видна, карточка сама объясняет почему: окно свёрнуто, место закрыто другим окном, элемент не найден.

## Настройки

`%LOCALAPPDATA%\TutorialOverlay\config.json` (все поля необязательны). Те же поля можно передать в spec
туториала — они действуют до его конца:

```json
{ "port": 7788, "lang": "ru", "accent": "#FF4D6D", "animate": true, "hideWhenInactive": true, "autoColor": true, "hideFromCapture": false,
  "hotkeys": { "done": "Ctrl+Alt+Right", "back": "Ctrl+Alt+Left", "skip": "Ctrl+Alt+Down", "undo": "Ctrl+Alt+Z", "stop": "none" } }
```

Окно настроек пишет файл атомарно; если `config.json` не читается (опечатка, сделанная руками), он сохраняется рядом
как `config.json.broken-<дата>`, а не теряется.

`autoColor` (по умолчанию `true`): цвет отметок подбирается под приложение — оверлей замеряет пиксели вокруг первой
цели шага и берёт из ярких цветов (пурпурный, оранжевый, жёлтый, голубой, красный, фиолетовый) самый непохожий на
интерфейс. Явный `color` в фигуре главнее. `lang`: `ru` или `en` (подписи карточки и подсказок). `"none"` отключает хоткей. Строка подсказок внизу карточки
строится из действующих хоткеев.

Хоткеи по умолчанию (действуют, пока видна карточка): **Ctrl+Alt+→** готово, **←** назад, **↓** пропустить,
**Z** отменить попадание, **X** стоп.

Хуки мыши и клавиатуры охраняет сторож. Если система видит ввод, а хуки молчат дольше 1,5 с, это не обязательно
поломка: часть ввода хуки не видят вовсе — прокрутку и жесты тачпада в программах, которые берут их напрямую (браузеры,
VS Code), ввод в окна, запущенные от администратора, экран входа и UAC. Поэтому сторож сначала проверяет хуки пробой:
посылает движение мыши на 1 px и обратно (курсор остаётся на месте). Дошла — хуки живы, в журнал раз в минуту пишется,
куда ушёл невидимый ввод. Не дошла — Windows хуки сняла (она делает это без предупреждения с хуком, который хоть раз
ответил слишком медленно): они ставятся заново, приходит событие `hook_reinstalled`, а в журнал пишется, отвечает ли
поток хуков, самый долгий ответ обработчика и паузы сборщика мусора. Поток хуков не даёт Windows притормаживать себя
ради экономии энергии.

## События

`ready`, `tutorial_started/finished/stopped/waiting`, `steps_appended`, `step_started/completed/back/skipped`,
`hit`, `unhit`, `miss`, `undo`, `check_changed`, `uia_changed`, `key_matched`, `drag`, `opened`, `no_effect`,
`button`, `help`, `sequence_reset`, `pick_started`, `pick`, `pick_finished`, `ask`, `answer`, `ask_area`, `area`,
`window_opened/closed`, `anchor_found/lost`,
`hook_reinstalled`, `exit`. У `miss` есть пометки `wrongButton` / `expectedButton`, если клик попал в цель не той
кнопкой мыши.

`hit` и `miss` содержат `rel` — смещение клика от точки якоря. По `miss` агент может поправить калибровку
смещения.

```json
{"event":"hit","seq":10,"ts":"19:31:46.689","mark":"s1t0","name":"Жирный","x":1023,"y":246,"button":"left","rel":[26,30],"step":1,"done":1,"required":3}
```

## Долгие вызовы

`ask`, `ask_area`, `pick` и `events` с ожиданием могут ждать пользователя минутами. Если клиент принимает
`text/event-stream`, ответ на такой вызов идёт потоком: каждые 10 с приходит `notifications/progress` (если клиент
прислал `_meta.progressToken`) или комментарий-пинг, а в конце — сам результат. Так ни тайм-аут клиента, ни простой
соединения не обрывают ожидание. Версия протокола MCP согласуется: сервер поддерживает 2025-06-18, 2025-03-26 и
2024-11-05.

## Расход токенов агента

Всё, что сервер отдаёт агенту, ложится в его контекст, поэтому ответы экономные:

- описания инструментов короткие (~3 тыс. токенов): полный формат якоря и фигур есть только у `draw`, остальные
  ссылаются на него;
- результаты — компактный JSON без пустых полей (на 40–50% короче JSON с отступами);
- `screenshot` по умолчанию уменьшает длинную сторону до 1024 px (снимок окна ≈ 0,8 тыс. токенов вместо ≈ 2 тыс.).
  Позиции это не сдвигает: `find_text`, якоря, `pick`, `status` и `validate` считают по полноразмерным пикселям.
  Если картинка уменьшена сильнее чем до 0,6, ответ сам предупреждает (`precision`): мерить по ней на глаз и читать
  мелкий текст не стоит — для этого `find_text`/`pick`, снимок одного элемента через `anchor` или `maxEdge: 0`;
- `find_text` возвращает не больше 5 совпадений (`max`) и один готовый якорь.

## Скриншоты и приватность

Сам оверлей экран не снимает. Полный снимок делается только по вызову `screenshot`. Пиксельная проверка читает
квадрат 3×3 в точке цели раз в 150 мс и только для целей с `check`.

Ваши скриншоты и записи экрана видят оверлей. Пиксельная проверка смотрит сквозь крошечную прозрачную «дырку»,
которую холст оставляет в точке замера. `screenshot()` агента на долю секунды исключает окна оверлея из захвата
(`includeOverlay: true` — снимок вместе с ними). Окна Ножниц, ShareX, Greenshot, OBS и подобных не считаются уходом
из приложения и не прячут отметки. Чтобы оверлей был невидим для любого захвата, задайте
`"hideFromCapture": true` в `config.json` или запустите с флагом `--hide-from-capture`.

## Тесты

Логика, не требующая экрана (разбор spec и сетки, проверка опечаток, пересчёт масштаба, пиксельные выражения,
хоткеи, сравнение текста OCR, буфер событий, файлы), покрыта тестами в `tests/` — обычная консольная программа без
тестовых фреймворков и пакетов NuGet. Запуск из корня репозитория:

```powershell
dotnet run --project tests            # все
dotnet run --project tests -- Lint    # только те, в чьём имени есть «Lint»
```

Код выхода — число упавших тестов.

## Примеры туториалов

Готовые туториалы (spec в JSON) в репозиторий не входят: папка `examples/` и библиотека туториалов
(`%LOCALAPPDATA%\TutorialOverlay\tutorials\`) хранятся только на своём компьютере, `examples/` указана в `.gitignore`.
Если такая папка есть, тесты проверяют, что в каждом туториале нет неизвестных полей и указан масштаб (`"scale"`),
при котором сняты его смещения; без неё эти тесты ничего не проверяют.
