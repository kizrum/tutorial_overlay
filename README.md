# TutorialOverlay

Экранный оверлей для пошаговых туториалов в любом приложении Windows. Управляется Claude Code через MCP.
Один exe на C# / .NET 8. Написан с нуля: без NuGet-пакетов и сторонних ассетов. Вся графика (кольца, стрелки,
иконки, галочки) рисуется векторно в коде. Текст выводится системным UI-шрифтом Windows через ОС, файлы шрифтов
в программу не входят.

## Сборка и запуск

```powershell
dotnet publish -c Release -o publish        # → publish\TutorialOverlay.exe (~350 КБ, нужен .NET 8 Desktop + ASP.NET runtime)
$env:TUTORIAL_OVERLAY_KEY = "<длинный-секрет>"
publish\TutorialOverlay.exe                  # http://127.0.0.1:7788/mcp
```

Параметры: `--port 7788`, `--key KEY`, `--no-anim`, `--show-inactive` (не прятать отметки, когда приложение
не на переднем плане), `--verbose`. Ключ берётся из `--key`, из переменной `TUTORIAL_OVERLAY_KEY` или из
`%LOCALAPPDATA%\TutorialOverlay\key.txt` (файл создаётся при первом запуске).

Порт по умолчанию — 7788, его можно поменять полем `port` в `config.json` (параметр `--port` главнее).

**Значок в трее** показывает, что сервер запущен: маленькая карточка шага. Полоска сверху во время туториала показывает
его прогресс, точка в углу зелёная, если агент обращался за последние 5 минут, серая — если нет. Подсказка при наведении: порт, когда агент
обращался последний раз, текущий туториал и шаг. Левый клик открывает настройки, правый — меню: «Настройки…»,
«Скопировать ключ», «Скопировать адрес MCP», «Открыть папку настроек», «Остановить туториал», «Закрыть TutorialOverlay».

**Окно настроек** (вкладки «Сервер», «Вид», «Горячие клавиши») пишет в `config.json` и сразу применяет изменения.
Если идёт туториал, язык, цвет и хоткеи из его spec действуют до его конца. Новый порт начинает работать после
перезапуска, окно предложит перезапустить сервер. Адрес в `.mcp.json` при этом нужно поменять самому.

Сервер слушает только `127.0.0.1`. Ключ принимается как `Authorization: Bearer`, `X-Overlay-Key` или `?key=`.
Чужие `Origin` отклоняются.

**stdout** — одно JSON-событие на строку, **stderr** — диагностика. Claude Code может запустить exe через
Monitor и реагировать на события без вопросов «готово?».

### Подключение к Claude Code

В корне репозитория лежит `.mcp.json` (сервер `tutorial-overlay`, ключ подставляется из `${TUTORIAL_OVERLAY_KEY}`).
Для другого проекта:

```
claude mcp add --transport http tutorial-overlay http://127.0.0.1:7788/mcp --header "Authorization: Bearer <ключ>"
```

## Инструменты MCP

| Инструмент | Что делает |
|---|---|
| `draw(shapes, anchor, dismissOnClick, …)` | отметки вне туториала; клик гасит отметку и доходит до приложения |
| `clear(id?)` | убрать отметки |
| `start_tutorial(spec)` | запустить туториал (показан только текущий шаг) |
| `append_steps(steps)` | дописать шаги (с `keepOpen` туториал ждёт их после последнего) |
| `goto_step(index\|id\|relative)` | перейти к шагу; цели снова показаны |
| `complete_step(expectIndex?)` | засчитать шаг от имени агента |
| `stop_tutorial()` | остановить |
| `status()` | состояние, прямоугольники целей и причина видимости (`visible/occluded/minimized/inactive/…`) |
| `describe(app)` | окна процесса и дерево UI Automation с физическими прямоугольниками и `rel`-смещениями |
| `screenshot(anchor)` | снимок окна/элемента **без** рисунков оверлея; `includeOverlay: true` — с ними |
| `events(since, timeoutMs)` | события с long-poll (дублирует stdout и MCP-уведомления) |
| `hint(text, title?, highlight?)` | ответ агента в карточке шага (например, после события `help`) |
| `pick(anchor, count, prompt)` | калибровка: пользователь кликает точку, агент получает смещение от якоря, цвет, элемент UIA и готовый `suggestedAnchor`; клик по умолчанию до приложения не доходит, Esc — отмена |
| `find_text(text?, anchor, within, match, lang)` | найти надпись на экране встроенным в Windows OCR: прямоугольник, центр, `rel` и `suggestedAnchor` с `find: {text}`; без `text` — весь распознанный текст области |
| `validate(spec?)` | проверить туториал до запуска (или текущий): по каждому шагу видна ли цель сейчас, а если нет — почему |
| `ask(question, options, input)` | спросить пользователя в панели над карточкой и дождаться ответа: кнопкой (`{choice, label}`) или текстом (`{text}`) |
| `ask_area(prompt)` | попросить обвести место на экране карандашом и дождаться: границы, штрихи, элемент UIA в центре и картинка области |

## Сущности

На холсте (клики проходят насквозь в приложение):

- `circle` — кольцо; `rect` — рамка (без `w/h` обводит элемент якоря); `arrow` — стрелка (сама целится в цель,
  хвост смотрит к центру экрана);
- `badge` — номер; `label` — подпись; `info` — инфо-блок с заголовком и значком;
- `check` — галочка; `checkbox` — чекбокс, который сам ставит ✓, когда цель выполнена (удобно для ячеек FL);
- `dim` — затемнение экрана с «окнами» на целях.

Кликабельные (отдельные окна, фокус у приложения не забирают):

- `button` — кнопка в любом месте экрана: `{text, id, action: done|next|back|skip|stop|undo|dismiss, style}`;
  шлёт событие `button`;
- **карточка шага** — «ШАГ n / N», прогресс, заголовок, текст, чек-лист целей, «Назад», «↶» (отменить последнее
  попадание), «Пропустить», «Готово», «✕» (стоп) и свои кнопки шага (`buttons`).

Раскладка без наложений: кольца соседних целей сужаются, подписи/инфо/кнопки без явных `x,y` ищут свободное
место вокруг цели (подпись встаёт у хвоста стрелки), карточка обходит всё нарисованное. Карточку можно
перетащить мышью — тогда она остаётся на месте.

## Якоря

```json
{ "process": "FL64", "window": "подстрока заголовка", "title": "окно ИЛИ Pane/Window в UIA",
  "element": [{ "name": "Channel rack", "role": "Pane" }, { "name": "…" }],
  "origin": "topleft|center|…", "offset": [dx, dy], "relativeTo": "frame|client" }
```

- Имена сравниваются подстрокой без учёта регистра. Из одноимённых элементов берётся самый большой
  (`pick: largest`). Это нужно для FL, где каждое подокно в UIA представлено двумя Pane.
- Резолвер просматривает **все** окна процесса, в том числе меню и диалоги. UIA опрашивается в фоновом потоке,
  а отметка каждый кадр берёт текущую позицию окна, поэтому едет за ним без задержки.
- Отметка прячется, если окно свёрнуто, закрыто, перекрыто другим окном или приложение не на переднем плане
  (`hideWhenInactive`, по умолчанию включено). Пока пользователь в другом окне, условия шага заморожены. При
  возврате всё появляется на том же шаге; если окно пересоздано, якорь находится заново.
- Клики сопоставляются по **процессу** окна под курсором, а не по заголовку.

**Якорь по тексту** — для программ, которые рисуют интерфейс сами и ничего не отдают в UIA (FL Studio):

```json
{ "process": "FL64", "element": { "name": "Channel rack" }, "find": { "text": "Kick", "match": "contains", "index": 0 }, "offset": [-40, 0] }
```

Надпись ищется встроенным в Windows распознаванием текста (`Windows.Media.Ocr`, вызывается напрямую через WinRT,
без дополнительных библиотек) по собственным пикселям окна, поэтому работает и под другими окнами. Точка якоря —
центр найденного текста, `offset` отсчитывается от него. Отметка следует за надписью при прокрутке (поиск раз в
0,7 с). `match`: `contains` (по умолчанию), `exact` (вся строка), `regex`; мелкие ошибки распознавания (l/I, 0/O)
прощаются. `index` — номер вхождения сверху вниз и слева направо, `within: [x,y,w,h]` — часть элемента, `lang` —
язык распознавания (по умолчанию языки пользователя). Как OCR прочитал область, показывает `find_text` без `text`.

**Проверка перед запуском** — `validate(spec)` разрешает все якоря туториала прямо сейчас. Ошибки (процесс не
запущен, шаблон не снят, шаг не разобран) нужно исправить. Предупреждения на поздних шагах часто означают то, что
откроет предыдущий шаг; `occluded` и `inactive` значат лишь, что сейчас впереди другое окно.

## Шаги и условия

```json
{ "id": "kick", "title": "…", "text": "…", "anchor": { … }, "toggle": true, "dim": 0.4, "numbered": true,
  "targets": [{ "name": "Шаг 1", "shapes": [ … ], "check": { "at": [335, 93], "expr": "g>140" },
                "button": "left|right|any", "optional": false, "doneStyle": "hide|check" }],
  "until": [ "all_clicked", { "type": "appear", "title": "Piano roll" }, { "type": "disappear", "title": "Piano roll" },
             { "type": "pixel", "anchor": { … }, "at": [x, y], "expr": "r>140 && g<100" }, { "type": "count", "count": 3 } ],
  "untilMode": "any|all", "buttons": [{ "id": "yes", "text": "Да" }], "controls": ["back", "undo", "skip", "done", "stop"] }
```

- Без `until`: шаг с целями завершается, когда кликнуты все цели. Шаг без целей ждёт «Готово», хоткей
  или `complete_step`.
- `disappear` срабатывает, только если цель сначала была замечена на экране.
- `toggle`: повторный клик по погашенной цели снова её зажигает. Если у цели есть `check`, состояние берётся
  из пикселя, и toggle получается сам собой.
- Выражения пиксельной проверки: каналы `r g b lum max min sat`, разность вида `r-g`, операторы
  `> >= < <= == !=`, связки `&&` и `||`, близость к цвету `~#1AD28F:40`.

Ещё условия:

- `{ "type": "key", "keys": ["F6", "Ctrl+S"] }` — нажато сочетание, пока приложение на переднем плане. Клавиши
  читаются только пока такое условие активно, и наружу сообщается только совпадение (`key_matched`): остальные
  нажатия нигде не записываются.
- `{ "type": "drag", "from": { "element": { "name": "Browser" } }, "to": { "element": { "name": "Channel rack" } } }` —
  перетаскивание из одной области в другую. Области: границы якоря, `rect:[x,y,w,h]` от точки якоря или `radius`.
  Рисуется как источник → стрелка → зона сброса.
- `{ "type": "uia", "element": { "name": "Bold" }, "property": "toggle", "equals": "on" }` — состояние элемента:
  `exists`, `name`, `value`, `toggle`, `selected`, `expanded`, `enabled`, `focused`, `text`. Сравнение —
  `equals`, `contains` или `matches` (regex), плюс `not`. При изменении значения приходит событие `uia_changed`.

**Клик, который открывает окно** — поле цели `opens`:

```json
{ "anchor": { … }, "opens": { "title": "Piano roll" } }                         // подокно внутри программы
{ "anchor": { … }, "opens": { "process": "chrome", "timeoutMs": 15000 } }        // окно другой программы
```

Цель засчитывается, только когда после клика появилось **новое** окно или панель: окно, которое было открыто
раньше, не считается. Если за `timeoutMs` (по умолчанию 6 с) ничего не появилось, цель остаётся гореть, а агенту
приходит `no_effect`; успех — событие `opened`. Пока пользователь работает в открывшемся окне другой программы,
шаг не замораживается, и его карточка остаётся видна.

**Цепочка внутри шага** — `"sequence": true`: цели показываются по одной, по порядку. Типичный случай — правый клик
по каналу, затем пункт в открывшемся меню:

```json
{ "sequence": true, "targets": [
  { "name": "Правый клик по FLEX Bass", "button": "right", "anchor": { "element": { "name": "Channel rack" }, "offset": [224, 272] } },
  { "name": "Пункт «Piano roll»", "anchor": { "windowClass": "TQuickPopupMenuWindow", "offset": [40, 120] },
    "opens": { "title": "Piano roll" } } ] }
```

Меню — отдельное окно процесса, поэтому якорем служит само окно меню. Без `offset` обводится всё меню; точное
место пункта снимается через `pick(anchor: { windowClass: … }, passThrough: true)`. Если меню закрылось, а нужный
пункт так и не выбрали, предыдущая цель загорается снова, и приходит событие `sequence_reset`.

**Сетка** — одна запись вместо многих целей:

```json
{ "name": "Шаг {col}", "grid": { "from": [335, 93], "step": [24, 45], "cells": [1, 5, 9, 13] }, "check": { "expr": "g>140" } }
```

`from` — центр первой ячейки относительно точки якоря, `step` — расстояние между центрами. Можно задать `rows`
и `cols` или список `cells` (`[[ряд, столбец], …]` или просто номера столбцов первого ряда, всё с единицы).
Фигура по умолчанию — чекбокс размера `w × h`. Значения `from` и `step` проще всего получить через
`pick(anchor, count: 2)` по двум соседним ячейкам: ответ содержит `gridHint`.

## Помощь пользователю

На карточке есть кнопка **«?»** (хоткей **Ctrl+Alt+H**). Она раскрывается в два варианта: **«Не вижу, куда жать»**
и **«Не понимаю, что делать»**.

- Агенту приходит событие `help`: причина, у каждой цели — видна ли она и почему (`visible`, `occluded`, `minimized`,
  `inactive`, `element not found`…) и где она на экране, последние промахи на шаге, активное окно и курсор.
- На «Не вижу» оверлей сам на 6 секунд затемняет экран вокруг целей и пускает от них волны.
- В окне «Другое» есть **карандаш** («Обвести»). Он замораживает картинку экрана, и пользователь обводит мышью место,
  о котором пишет. Enter или правый клик — готово, Ctrl+Z или Backspace — убрать последний штрих, Delete — стереть всё,
  Esc — выйти без изменений. Повторное нажатие на карандаш дорисовывает к уже сделанному. Обводка остаётся на экране
  до ответа агента. В событии `help` появляется поле `sketch`: `bounds` и `center` в пикселях экрана, `strokes`
  (у каждого штриха `shape`: `loop` | `line` | `dot`, `from`, `to` и до 48 точек), `atCenter` (окно, цвет и элемент UIA
  в центре обводки, `rel` от якоря первой цели шага, `suggestedAnchor`) и `image` — путь к PNG с этим местом и обводкой
  в `%LOCALAPPDATA%\TutorialOverlay\help\`.
- Ответ агента — инструмент `hint(text, title?, highlight?)`: текст появляется прямо в карточке текущего шага. До
  ответа карточка пишет «Передал ассистенту — сейчас подскажу».
- Если цель не видна, карточка сама объясняет почему: окно свёрнуто, место закрыто другим окном, элемент не найден.

## Настройки

`%LOCALAPPDATA%\TutorialOverlay\config.json` (все поля необязательны). Те же поля можно передать в spec
туториала — они действуют до его конца:

```json
{ "port": 7788, "lang": "ru", "accent": "#FF4D6D", "animate": true, "hideWhenInactive": true, "autoColor": true, "hideFromCapture": false,
  "hotkeys": { "done": "Ctrl+Alt+Right", "back": "Ctrl+Alt+Left", "skip": "Ctrl+Alt+Down", "undo": "Ctrl+Alt+Z", "stop": "none" } }
```

`autoColor` (по умолчанию `true`): цвет отметок подбирается под приложение — оверлей замеряет пиксели вокруг первой
цели шага и берёт из ярких цветов (пурпурный, оранжевый, жёлтый, голубой, красный, фиолетовый) самый непохожий на
интерфейс. Явный `color` в фигуре главнее. `lang`: `ru` или `en` (подписи карточки и подсказок). `"none"` отключает хоткей. Строка подсказок внизу карточки
строится из действующих хоткеев.

Хоткеи по умолчанию (действуют, пока видна карточка): **Ctrl+Alt+→** готово, **←** назад, **↓** пропустить,
**Z** отменить попадание, **X** стоп.

Хуки мыши и клавиатуры охраняет сторож: если система видит ввод, а хуки молчат дольше 1,5 с (Windows снимает
медленные хуки без предупреждения), они ставятся заново, и приходит событие `hook_reinstalled`.

## События

`ready`, `tutorial_started/finished/stopped/waiting`, `steps_appended`, `step_started/completed/back/skipped`,
`hit`, `unhit`, `miss`, `undo`, `check_changed`, `uia_changed`, `key_matched`, `drag`, `opened`, `no_effect`,
`button`, `help`, `sequence_reset`, `pick_started`, `pick`, `pick_finished`, `ask`, `answer`, `ask_area`, `area`,
`window_opened/closed`, `anchor_found/lost`,
`hook_reinstalled`, `exit`. У `miss` есть пометки `wrongButton` / `expectedButton`, если клик попал в цель не той
кнопкой мыши.

`hit` и `miss` содержат `rel` — смещение клика от точки якоря. По `miss` агент может поправить калибровку
смещения.

```json
{"event":"hit","seq":10,"ts":"19:31:46.689","mark":"s1t0","name":"Жирный","x":1023,"y":246,"button":"left","rel":[26,30],"step":1,"done":1,"required":3}
```

## Скриншоты и приватность

Сам оверлей экран не снимает. Полный снимок делается только по вызову `screenshot`. Пиксельная проверка читает
квадрат 3×3 в точке цели раз в 150 мс и только для целей с `check`.

Ваши скриншоты и записи экрана видят оверлей. Пиксельная проверка смотрит сквозь крошечную прозрачную «дырку»,
которую холст оставляет в точке замера. `screenshot()` агента на долю секунды исключает окна оверлея из захвата
(`includeOverlay: true` — снимок вместе с ними). Окна Ножниц, ShareX, Greenshot, OBS и подобных не считаются уходом
из приложения и не прячут отметки. Чтобы оверлей был невидим для любого захвата, задайте
`"hideFromCapture": true` в `config.json` или запустите с флагом `--hide-from-capture`.

## Примеры

- `examples/notepad.json` — меню, три цели с номерами и чек-листом, инфо-блок с кнопкой.
- `examples/fl_studio.json` — открытие стойки (окно или F6), ячейки Channel rack сеткой с пиксельной проверкой,
  правый клик с `opens` на Piano roll, закрытие Piano roll. Смещения замерены на FL Studio 2025 при масштабе 165%; на другой раскладке перемерьте их через
  `screenshot(anchor)`.
