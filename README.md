# TutorialOverlay

Экранный оверлей для пошаговых туториалов в любом приложении Windows. Управляется Claude Code через MCP.
Один exe на C# / .NET 8. Написан с нуля: без NuGet-пакетов и сторонних ассетов. Вся графика (кольца, стрелки,
иконки, галочки) рисуется векторно в коде. Текст выводится системным UI-шрифтом Windows через ОС, файлы шрифтов
в программу не входят.

## Сборка и запуск

```powershell
dotnet publish -c Release -o publish        # → publish\TutorialOverlay.exe (~350 КБ, нужен .NET 8 Desktop + ASP.NET runtime)
$env:TUTORIAL_OVERLAY_KEY = "<длинный-секрет>"
publish\TutorialOverlay.exe                  # http://127.0.0.1:7788/mcp
```

Параметры: `--port 7788`, `--key KEY`, `--no-anim`, `--show-inactive` (не прятать отметки, когда приложение
не на переднем плане), `--verbose`. Ключ берётся из `--key`, из переменной `TUTORIAL_OVERLAY_KEY` или из
`%LOCALAPPDATA%\TutorialOverlay\key.txt` (файл создаётся при первом запуске).

Сервер слушает только `127.0.0.1`. Ключ принимается как `Authorization: Bearer`, `X-Overlay-Key` или `?key=`.
Чужие `Origin` отклоняются.

**stdout** — одно JSON-событие на строку, **stderr** — диагностика. Claude Code может запустить exe через
Monitor и реагировать на события без вопросов «готово?».

### Подключение к Claude Code

В корне репозитория лежит `.mcp.json` (сервер `tutorial-overlay`, ключ подставляется из `${TUTORIAL_OVERLAY_KEY}`).
Для другого проекта:

```
claude mcp add --transport http tutorial-overlay http://127.0.0.1:7788/mcp --header "Authorization: Bearer <ключ>"
```

## Инструменты MCP

| Инструмент | Что делает |
|---|---|
| `draw(shapes, anchor, dismissOnClick, …)` | отметки вне туториала; клик гасит отметку и доходит до приложения |
| `clear(id?)` | убрать отметки |
| `start_tutorial(spec)` | запустить туториал (показан только текущий шаг) |
| `append_steps(steps)` | дописать шаги (с `keepOpen` туториал ждёт их после последнего) |
| `goto_step(index\|id\|relative)` | перейти к шагу; цели снова показаны |
| `complete_step(expectIndex?)` | засчитать шаг от имени агента |
| `stop_tutorial()` | остановить |
| `status()` | состояние, прямоугольники целей и причина видимости (`visible/occluded/minimized/inactive/…`) |
| `describe(app)` | окна процесса и дерево UI Automation с физическими прямоугольниками и `rel`-смещениями |
| `screenshot(anchor)` | снимок окна/элемента **без** рисунков оверлея; `includeOverlay: true` — с ними |
| `events(since, timeoutMs)` | события с long-poll (дублирует stdout и MCP-уведомления) |

## Сущности

На холсте (клики проходят насквозь в приложение):

- `circle` — кольцо; `rect` — рамка (без `w/h` обводит элемент якоря); `arrow` — стрелка (сама целится в цель,
  хвост смотрит к центру экрана);
- `badge` — номер; `label` — подпись; `info` — инфо-блок с заголовком и значком;
- `check` — галочка; `checkbox` — чекбокс, который сам ставит ✓, когда цель выполнена (удобно для ячеек FL);
- `dim` — затемнение экрана с «окнами» на целях.

Кликабельные (отдельные окна, фокус у приложения не забирают):

- `button` — кнопка в любом месте экрана: `{text, id, action: done|next|back|skip|stop|undo|dismiss, style}`;
  шлёт событие `button`;
- **карточка шага** — «ШАГ n / N», прогресс, заголовок, текст, чек-лист целей, «Назад», «↶» (отменить последнее
  попадание), «Пропустить», «Готово», «✕» (стоп) и свои кнопки шага (`buttons`).

Раскладка без наложений: кольца соседних целей сужаются, подписи/инфо/кнопки без явных `x,y` ищут свободное
место вокруг цели (подпись встаёт у хвоста стрелки), карточка обходит всё нарисованное. Карточку можно
перетащить мышью — тогда она остаётся на месте.

## Якоря

```json
{ "process": "FL64", "window": "подстрока заголовка", "title": "окно ИЛИ Pane/Window в UIA",
  "element": [{ "name": "Channel rack", "role": "Pane" }, { "name": "…" }],
  "origin": "topleft|center|…", "offset": [dx, dy], "relativeTo": "frame|client" }
```

- Имена сравниваются подстрокой без учёта регистра. Из одноимённых элементов берётся самый большой
  (`pick: largest`). Это нужно для FL, где каждое подокно в UIA представлено двумя Pane.
- Резолвер просматривает **все** окна процесса, в том числе меню и диалоги. UIA опрашивается в фоновом потоке,
  а отметка каждый кадр берёт текущую позицию окна, поэтому едет за ним без задержки.
- Отметка прячется, если окно свёрнуто, закрыто, перекрыто другим окном или приложение не на переднем плане
  (`hideWhenInactive`, по умолчанию включено). Пока пользователь в другом окне, условия шага заморожены. При
  возврате всё появляется на том же шаге; если окно пересоздано, якорь находится заново.
- Клики сопоставляются по **процессу** окна под курсором, а не по заголовку.

## Шаги и условия

```json
{ "id": "kick", "title": "…", "text": "…", "anchor": { … }, "toggle": true, "dim": 0.4, "numbered": true,
  "targets": [{ "name": "Шаг 1", "shapes": [ … ], "check": { "at": [335, 93], "expr": "g>140" },
                "button": "left|right|any", "optional": false, "doneStyle": "hide|check" }],
  "until": [ "all_clicked", { "type": "appear", "title": "Piano roll" }, { "type": "disappear", "title": "Piano roll" },
             { "type": "pixel", "anchor": { … }, "at": [x, y], "expr": "r>140 && g<100" }, { "type": "count", "count": 3 } ],
  "untilMode": "any|all", "buttons": [{ "id": "yes", "text": "Да" }], "controls": ["back", "undo", "skip", "done", "stop"] }
```

- Без `until`: шаг с целями завершается, когда кликнуты все цели. Шаг без целей ждёт «Готово», хоткей
  или `complete_step`.
- `disappear` срабатывает, только если цель сначала была замечена на экране.
- `toggle`: повторный клик по погашенной цели снова её зажигает. Если у цели есть `check`, состояние берётся
  из пикселя, и toggle получается сам собой.
- Выражения пиксельной проверки: каналы `r g b lum max min sat`, разность вида `r-g`, операторы
  `> >= < <= == !=`, связки `&&` и `||`, близость к цвету `~#1AD28F:40`.

Хоткеи (действуют, пока видна карточка): **Ctrl+Alt+→** готово, **←** назад, **↓** пропустить, **Z** отменить
попадание, **X** стоп.

## События

`ready`, `tutorial_started/finished/stopped/waiting`, `steps_appended`, `step_started/completed/back/skipped`,
`hit`, `unhit`, `miss`, `undo`, `check_changed`, `button`, `window_opened/closed`, `anchor_found/lost`, `exit`.

`hit` и `miss` содержат `rel` — смещение клика от точки якоря. По `miss` агент может поправить калибровку
смещения.

```json
{"event":"hit","seq":10,"ts":"19:31:46.689","mark":"s1t0","name":"Жирный","x":1023,"y":246,"button":"left","rel":[26,30],"step":1,"done":1,"required":3}
```

## Скриншоты и приватность

Сам оверлей экран не снимает. Полный снимок делается только по вызову `screenshot`. Пиксельная проверка читает
квадрат 3×3 в точке цели раз в 150 мс и только для целей с `check`. Окна оверлея помечены
`WDA_EXCLUDEFROMCAPTURE`, поэтому в снимки и пиксельные пробы не попадают.

## Примеры

- `examples/notepad.json` — меню, три цели с номерами и чек-листом, инфо-блок с кнопкой.
- `examples/fl_studio.json` — ячейки Channel rack с пиксельной проверкой, правый клик, появление и закрытие
  Piano roll. Смещения замерены на FL Studio 2025 при масштабе 165%; на другой раскладке перемерьте их через
  `screenshot(anchor)`.
